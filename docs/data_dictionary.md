## 1. Overview & Conventions

This data dictionary formally specifies the relational data model for the ExamOps platform. Every entity, attribute, data type, nullability constraint, validation rule, unit, foreign key reference, and lifecycle semantic is defined below.

### Standard Nomenclature Conventions

| Entity | Public Identifier Pattern | Example |
|---|---|---|
| Student | `STU-<06d>` | `STU-000001` |
| Course | `CRS-<06d>` | `CRS-000001` |
| Enrollment | `ENR-<06d>` | `ENR-000001` |
| Exam | `EXAM-<YYYY>-<06d>` | `EXAM-2026-000001` |
| ExamRequirement | `REQ-<06d>` | `REQ-000001` |
| Room | `ROOM-<06d>` | `ROOM-000001` |
| RoomCapacity | `CAP-<06d>` | `CAP-000001` |
| Invigilator | `INV-<06d>` | `INV-000001` |
| Availability | `AVL-<06d>` | `AVL-000001` |
| Accommodation | `ACO-<06d>` | `ACO-000001` |
| ScheduleAssignment | `ASN-<exam-code>-<room-code>` | `ASN-EXAM-2026-000001-ROOM-000001` |
| SchedulingRun | `RUN-<YYYYMMDD>-<04d>` | `RUN-20261022-0001` |

### Primary Key & Idempotency Strategy
- All tables employ an internal surrogate primary key `id` of type `UUID` (generated by PostgreSQL `gen_random_uuid()`).
- All business identifiers (`student_code`, `room_code`, etc.) have explicit `UNIQUE NOT NULL` constraints.
- In `ScheduleAssignment`, `id` is a UUID PK, while `assignment_code` follows `ASN-<exam-code>-<room-code>`. The compound unique constraint `UNIQUE (scheduling_run_id, assignment_code)` allows historical runs to maintain stable assignment naming without collision.

## 8. Indexing Strategy & Performance Considerations

1. **Foreign Key Indexes:**
   Every single foreign key column (`student_id`, `course_id`, `exam_id`, `room_id`, `invigilator_id`, `scheduling_run_id`, `academic_period_id`) has an explicit B-tree index to eliminate sequential scans during JOINs.
2. **Conflict Overlap Indexing:**
   `schedule_assignments (scheduling_run_id, start_time, end_time)` is indexed to accelerate temporal overlap queries.
3. **Capacity Date-Range Queries:**
   `room_capacities (room_id, effective_start, effective_end)` accelerates point-in-time capacity lookups.
4. **Active State Filtering:**
   Partial index on `accommodations (student_id) WHERE is_active = TRUE` ensures instant lookup during exam duration calculation.
5. **Audit Chronology:**
   `audit_logs (created_at DESC)` and `schedule_events (created_at DESC)` ensure rapid page rendering for administrators.
